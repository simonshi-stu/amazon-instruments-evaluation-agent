| 为什么先做统计工具，不先微调？ | 先有可靠测量，才能知道模型错在哪里。 | Demo 手算测试；真实 LLM 成绩未测。 |

| Prompt 怎么确定？ | 根据开发集错误类型调整指令、历史证据格式、输出结构与拒绝条件。 | 尚无本轮 Prompt 优化成绩；不能用测试集反复调参。 |

| 如何降低幻觉？ | 数学交给代码；模型只解释证据；引用、数字、方向和分母校验；不足时拒绝下结论。 | Demo 没有模型生成解释，因此不能宣称已降低真实模型幻觉率。 |
| 改善措施效果如何？ | 只能报告实际测得的前后对照。 | 待记录错误率、样本量、额外耗时、失败与成本；未测标未知。 |
| 为什么选 MAE、RMSE、±1 星和偏差？ | MAE 直观，RMSE 放大大错，±1 星反映容忍范围，偏差揭示系统性高估／低估。 | 合成手算测试；用户评分不等于商品客观质量。 |
| 为什么必须展示覆盖率？ | 少量容易任务成功可能带来漂亮误差；失败不能从分母中消失。 | survivor 场景 B 仅 3/12 成功；共同任务比较单独报告。 |
| 为什么按同任务配对、按用户聚类？ | 避免不同任务难度及同一用户相关性造成假改善。 | 当前 Demo 有共同任务对齐；用户级 bootstrap 与区间尚未实现，不报告显著性。 |
| Memory 有没有用？ | 需确认历史实际进入 Prompt，再同任务比较有／无记忆。 | 未做真实实验；模式名称和合成差值不是 Memory 收益。 |
| 老用户和新用户怎样分别测？ | 老用户按时间留出未来；新用户按用户独立留出，调参只用开发集。 | 独立真实 cohort、泄漏检查与最终 holdout 成绩待实现。 |
| 为什么区分合成与真实数据？ | 合成数据验证计算、边界和流程；真实数据才检验现实效果。 | 当前在线页面仅合成、无真实数据外发。 |
| 为什么不立刻 QLoRA？ | 先排除数据、Prompt、检索和评测问题；微调不是默认解法。 | 将来确有残余问题，再比较基模／Prompt／检索／QLoRA，并记录 Colab 资源与许可。 |
| 什么条件算工程可用？ | 可复现、版本／来源可追踪、失败可见、隐私和预算受控、回归测试、人工审批。 | 当前仅契约与合成可视化阶段；真实实验、模型解释和批准报告导出未完成。 |

## 本轮实际记录

- 选择 GitHub Pages 而非立即部署 Python/LLM 服务：无密钥、无模型费用，浏览器即可说明评测口径。
- Python 在 CI 构建时真正计算合成指标；网页展示预计算报告，不假装点击时执行模型或后端。
- 示例下载是合成演示文件，不等同于未来绑定 evidence/config/report 哈希的人工批准导出。
- 当前没有公开原始评论、真实标签、逐任务私有实验或模型密钥。上线地址和测试结果以 README 的实际发布记录为准。
