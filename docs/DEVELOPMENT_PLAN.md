日期：2026-10-14。此文为逐步方案，不是完整 Agent 已交付的证明。

## 2026-10-18 增量与用户确认路线

用户确认按“找回源码 → 补齐评测 → 小规模真实 LLM → Prompt/检索优化 → Memory 对照 → 老用户未来行为与新用户独立泛化 → 必要时 Colab QLoRA”推进。AgentSociety＋Prompt＋LLM＋检索＋受控 Memory 是 A 生成侧路线，B 保持独立评测，不强制加入 LangChain 或向量库。

为便于外行理解，提前交付合成可视化 Demo，但不跳过后续真实实验门槛。新增 Python 确定性示例评分、共同任务比较和 Pages 展示；真实模型、人评、用户级区间、Memory 与泛化收益尚未验证。A 公开 main 已恢复，原新版契约镜像仍缺失；三项跨仓测试明确跳过，不能伪称新版恢复。

持续记录见 [中文面试问答](INTERVIEW_NOTES.zh-CN.md)。每次方法、模型或 Prompt 变更填写选择理由、替代方案、实际对照、样本／分母、效果与局限；没有做过就不写成尝试过或已改善。

## 2. 分步实现与验收

### 第一步：结果契约已验收；评测目标配置待做

- 目标：读取 A 输出，不依赖 A 应用入口；确认本次要比较谁、哪些任务及哪些指标。
- 已实现：schema/version/source/manifest/config 指纹格式、严格大小/类型/四态和诊断不变量检查，dry-run 无模型调用无产物；B 用标准库可独立运行。
- 已验收：fake 不被标成真实成绩；重复 task 身份/执行次序、非法 split 拒绝；无 GT/prompt/key/path 字段；错误非零安全类别；合成及已核验 prepared 前 3 任务的 fake A→B 互通通过。
- 仍待做：typed 评测配置与人工确认、独立来源/manifest 重算、真实 cohort 和 split 对齐。现有指纹只是声明，不代表外部核验；正文也不自动脱敏。
- 提示：先验证两条合成预测，不急着生成漂亮报告。配置确认不是数据许可确认。

### 第二步：注册可核验评测工具

拟工具职责（名称是设计，不代表都已实现）：

| 工具 | 输出证据 |
| --- | --- |
| `check_dataset` | 来源哈希、schema、许可状态、资源门槛 |
| `check_temporal_protocol` | 冻结切点、目标排除、split/任务数、协议哈希 |
| `calculate_baselines` | 固定四基线结果与冷启动计数 |
| `score_predictions` | RMSE/MAE/±1/bias、成功与回退分开、覆盖分母 |
| `diagnose_reviews` | 长度偏差、重合、无依据主张候选、人评来源 |
| `compare_schemes` | 对应共同任务、排除原因、用户级配对区间、暴露覆盖 |
| `summarize_run` | 首次格式、修复三类计数、四态、attempt、耗时与 usage 状态 |

工具从已确认配置获取权限，不允许模型任意查询用户、时间、路径或 SQL。真实数据/标签只在获准本地工具内读取。模型解释只接收脱敏汇总，不读取原始评论。

验收先用手算、空样本、单 cluster、失败/回退、错 task join 反例；继承 P0 大小门槛和 provider 全量重建，不只检查文件名。

### 第三步：公平比较与指标口径

评分误差为预测减实际。±1 准确率按 `abs(error)<=1`。模型 success-only、系统含 fallback、全请求四态三套分母都报告。

有无 Memory 共用相同任务、顺序、模型参数、历史/参考与预算。比较在对应共同有效的测试 cohort 上计算，同时展示原始覆盖和条件选择偏差。按整用户重采样，各方案共享同次抽样。

少于两个有效用户 cluster 或没有共同任务，不编造区间。无实际 prompt 纳入时，不把模式名解释为 Memory 效果；稀疏召回仍需说明无法判断。

长度和 8-gram 重合是文本代理，不能代替事实核验或风格人评。无历史标 NA；短文本重合零值也须说明信息不足。历史课程成绩与当前基线/fake/真实模型严格分开。

### 第四步：只解释工具证据

设计 `MetricEvidence`：固定指标名、值、样本数/分母、split、来源/配置/cohort 哈希、区间、计算方法、状态和限制。工具结果形成带版本与 evidence_id 的不可变证据包。

解释输出拟采用结构化 `ReportClaim`：主张类别、对应 evidence_id、引用数值、比较对象和限制，而不是一段不受约束的营销文字。

规则校验：

1. 引用 ID 必须在本次工具结果中，不能引用另一次运行。
2. 数值、方向、分母、区间须匹配工具值；若允许四舍五入，显式采用同一格式规则。
3. fake 或历史结果不能输出新版真实 LLM 成绩；Memory 暴露不足不能输出收益因果结论。
4. 区间跨零不能声称该比较已有明确改善证据；区间不跨零也不等于普遍稳定效果或已控制多重比较。
5. 未计算 p 值不能发明 p 值；工具状态为不足/unknown 时结论必须保留不足/unknown。
6. 不允许解释器自行计算指标或改变 cohort；需要新分析就调用获准工具，重新确认版本。
7. 校验不通过最多一次预算允许的修复；仍失败用确定性事实模板或拒绝解释，不伪装成功。

数值和来源校验能自动化，但不能证明自由文本语义永远正确。高风险结论限制为工具允许的类别，并人工核对；不宣称全面消除幻觉。

### 第五步：确认后导出与独立 Demo

报告先为 draft。人工确认绑定 report/evidence/config 哈希；工具值或配置变化则使确认失效。只有 approved 版本正式导出；原文件拒覆盖。

报告应包含数据协议、请求/有效/排除数量、指标、coverage、诊断、比较区间、限制和来源状态。默认不含评论、标签、原始用户 ID、prompt 或密钥。

B Demo 演示确认配置→工具→报告证据→解释校验→人工确认，区别于 A 的个性化生成 Demo。测试伪造数值/改善、跨 run 引用、确认后篡改、空/单 cluster、未批准导出和私有 marker。

## 3. 人工评论评测（待授权）

建议 20 个有安全历史的配对任务×两条件=40 文本，两名真实评审者，各评分风格与评分—评论一致性，1–5 分锚定量表。分别报告两维度、有效数量、分歧与评分来源。

风格：1 明显偏离，3 部分匹配，5 整体匹配历史；一致性：1 明显冲突，3 有歧义，5 表达与评分一致。盲化条件并随机排序，有效文本不足如实报告，不生成“人工评分”。人评成功文本样本不替代全任务失败覆盖。

调整 prompt 的人评取开发/验证任务；测试人评只作末端验证，不能用其反馈调模型后重复报告同一测试集为独立 holdout。

实际评审者、数据展示范围、样本量与费用需用户先确认。LLM judge 只能另标机器评分，不能冒充人工来源；本轮不运行 judge。

## 4. 记忆如何在两个项目中分工

A 保存生成记忆或未来获准真实行为；B 读取运行诊断评估候选→合格→选择→prompt→写入与用户覆盖。B 不把解释报告写回 A 当用户偏好，不增加第三个 Amazon Agent。

当前 A 的生成 store 运行内、不持久化；跨运行真实事件 SQLite 尚未实施。持久化后仍扣留目标/副本、保持截至时间、来源和 run/config 隔离。

## 5. 验收与面试口径

阶段依次通过：独立契约入口→工具数学/时间核验→配对诊断→受证据约束解释→批准导出/独立 Demo。每一步有代码、测试、范围和剩余限制，不把“派发过”当“完成”。

可写文案：

- 基于公开乐器评论构建时间安全的统计评测与运行诊断工具链。
- 实现工具证据驱动的报告解释、指标引用校验与版本化人工确认导出。

对应功能未通过前不使用完成时态；真实模型/人评/Memory 收益只能在实际获批测量后填写。

所有项目与本地产物位于 E 盘。真实模型调用、数据外发、人工评测或付费服务先确认；无价格/usage 就报告 unknown，不以 token 启发式承诺美元硬封顶。
